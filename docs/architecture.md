# 架构说明

## 组件边界

| 组件 | 责任 | 不负责 |
| --- | --- | --- |
| HTTPS 反向代理 | TLS、域名、路径转发 | 回调验签、业务处理 |
| Bridge | 回调、同步、幂等、状态、知识检索、转人工 | 模型推理、企业业务写操作 |
| Hermes Agent | 会话推理和回复生成 | 企业微信凭证、外网回调 |
| 企业微信 API | 消息、会话状态、发送 | Agent 会话与知识库 |
| SQLite | 游标、消息、会话和发送状态 | 长期分析仓库、权限系统 |

## 入站消息流程

1. 企业微信向 `/callbacks/wecom/kf` 发送加密事件。
2. Bridge 校验签名、解密 XML，并验证 `open_kfid` 白名单。
3. 回调中的短期拉取 Token 被写入队列；HTTP 请求立即返回 `success`。
4. 后台 worker 调用 `sync_msg`，分页拉取消息并保存游标。
5. `msgid` 唯一约束阻止重复处理。
6. 消息处理器检查客服状态、人工锁和消息类型。
7. 文本消息进入隔离的 Hermes Session；可选知识检索只注入相关片段。
8. 回复以确定性 `msgid` 发送，发送状态持久化以避免重复回复。

## 会话与转人工

外部会话键由 CorpID、`open_kfid`、`external_userid` 和会话代数构成，传给 Hermes 前会散列，避免直接暴露客户标识。

以下情况会触发转人工：

- 客户明确要求人工客服；
- 非文本消息；
- Hermes 创建会话或生成回复失败；
- 回复命中基础安全拒绝规则。

检测到人工接待状态后，Bridge 不再自动回复。客户重新进入可自动接待状态时，会话代数递增并创建新的 Hermes Session。

## 故障语义

- 回调校验失败：返回 403，不入队。
- API 短暂失败：任务保留并重试，错误只记录类型，避免泄密。
- Hermes 失败：转人工并锁定自动回复。
- 进程重启：SQLite 中的游标、去重和待处理状态保留。
- 重复回调：依靠回调队列和 `msgid` 唯一约束实现幂等。
