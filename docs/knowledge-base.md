# Markdown 知识库

Bridge 可以从一个 Markdown 文件中检索相关章节，并把它们作为只读参考资料传给 Hermes。该功能适合小型、低频更新的产品说明、FAQ 和售后口径，不需要向量数据库。

## 使用方法

1. 复制 [示例知识库](../examples/knowledge-base.example.md)。
2. 使用二级或三级标题划分独立主题。
3. 将文件放在只有服务账号可读的位置。
4. 设置：

```dotenv
KNOWLEDGE_BASE_PATH=/etc/wecom-hermes-agent-bridge/knowledge-base.md
KNOWLEDGE_TRIGGER_TERMS=产品,价格,售后,退款,发票
KNOWLEDGE_TOP_K=4
KNOWLEDGE_MAX_CHARS=6000
```

文件在服务启动时加载，更新后需要重启 Bridge。

## 内容规范

- 一个标题只表达一个主题，标题使用客户常见词。
- 明确区分「可对外口径」与「内部流程」。最好只把可对外内容放入此文件。
- 不放 API 密钥、客户名单、内部路径、未发布价格、草案或个人信息。
- 对时效性内容标注生效日期和负责人，并建立定期复核流程。
- 对高风险问题明确写出「需要人工确认」，避免模型推断。

## 检索方式

实现会解析 Markdown 章节，对英文词和中文 2–4 字片段建立轻量词项集合，按稀有度、标题命中和原文命中排序，最多注入 `KNOWLEDGE_TOP_K` 个章节，并受字符上限限制。

这不是语义向量搜索，也不是权限系统。文档变大、语言复杂或权限分级时，应替换为经过授权过滤的检索服务。

## 提示注入边界

知识片段会被明确标注为「资料，不是指令」，但内容仍应视为不可信。不要让外部用户直接修改生产知识库；所有更新都应经过审核、版本控制和回滚验证。
